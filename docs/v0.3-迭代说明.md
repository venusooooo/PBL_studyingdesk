# v0.3 迭代说明

> 这一版的目标从"跑通"转向"能长期用、能拿出去讲"。下面每一项都写清：解决什么问题、怎么实现、怎么验证。

## 一、番茄钟：从"单次倒计时"到完整循环

**问题**：v0.2 只有一个 25 分钟的 `Timer`，结束就重置，没有提示，用户切到别的窗口就完全不知道结束。

**实现**（`TodayPage`）：

| 阶段 | 时长 | 结束后 |
| --- | --- | --- |
| 专注 | 25 分钟 | 记一条 `FocusRecord`，番茄数 +1，进入短休 |
| 短休 | 5 分钟 | 进入下一轮专注 |
| 长休 | 15 分钟 | 每完成 4 个番茄触发一次，之后计数归零 |

- 结束提示：`TrayIcon.displayMessage` 弹系统通知 + `Toolkit.getDefaultToolkit().beep()` 提示音，两者都是 JDK 自带。
- 今日面板显示「今日 N 个番茄 · M 分钟」，`Store.pomodoroToday()` 直接按 `FocusRecord.label` 统计，不额外存字段。

**验证**：`FeatureSmokeTest` 断言今日番茄数为 2、专注时长累加为 75 分钟（示例数据 3 门课 + 6 课时场景）。

## 二、学习统计页：三张自绘图

**问题**：专注记录、任务完成、错题掌握度三组数据一直只以数字出现，看不到趋势。

**实现**（`StatsPage`，纯 `Graphics2D`）：

1. **专注热力图**：近 12 周 × 7 天，5 级色阶；格子边长随卡片宽度自适应（10~26px）；鼠标悬停显示「几月几日 · 星期几 · N 分钟」。右侧配「近 12 周总计 / 有记录天数 / 最多的一天」小结。
2. **每周任务完成率**：近 8 周柱状图，柱高 = 已完成 / 当周到期任务，无任务的周显示「—」，避免把 0% 和"没有任务"混为一谈。
3. **错题掌握度分布**：未掌握 / 复习中 / 已掌握三段横向条，右侧给出数量与占比。

底部「数据洞察」按当前数据生成 1~4 条结论（活跃天数、连续天数、本周任务完成情况、错题最多的课程）。

**验证**：离屏渲染 `StatsPage` 到图片，检查三张图的实际像素高度为 168/190/190，确认不是空白。

## 三、课表：单双周 + `.ics` 导出 + 页内建课

**单双周**：`Lesson` 增加 `weeks`（`ALL` / `ODD` / `EVEN`）。渲染时用 `lesson.occursIn(currentWeek)` 过滤，冲突校验用 `Lesson.weeksOverlap()` —— 单周课和双周课可以排在同一格，两节单周课不行。

**`.ics` 导出**（`IcsExporter`）：手拼 `VCALENDAR` / `VEVENT`，单周与双周分别写成 `RRULE:FREQ=WEEKLY;INTERVAL=2` 配 `BYDAY`，这样导入手机日历后能真正按周重复。文本按 RFC 5545 转义（`\` `;` `,` 换行），`UID` 用课程 id + 星期 + 节次生成，重复导入不会产生一堆重复事件。

**页内建课**：原来课表页想排课必须先跳到「课程与课时」建课，不建就只弹一句提示。现在：

- 工具栏有「+ 新建课程」；
- 没课程时点「+ 添加课时」，**直接弹出新建课程**，建完继续排课；
- 添加课时的弹窗里，课程下拉框右侧还有「+ 新建课程」，建完自动选中，不用关掉重开。

课程表单抽成 `CourseEditor`，课程页与课表页共用同一套字段、校验与配色，避免两处逻辑走样。

## 四、AI 助手侧栏

**实现**（`AiPanel` / `AiClient` / `AiConfig`）：

- 用 JDK 11 自带的 `java.net.http.HttpClient`，不引任何第三方库；
- 兼容 OpenAI 风格的 `/chat/completions`，接口地址、模型、Key 在「设置」里填，存到用户目录的 `ai.properties`，**不进仓库**；
- 三个预设：把一段话拆成带截止日的任务、根据错题出同类练习、生成今日与本周总结；
- 网络请求全部放在 `SwingWorker` 里，主线程只负责更新文本，界面不会卡；
- 没配置 Key 时侧栏显示"未配置 API Key，点右上角设置"，不会假装能用。

## 六、这一版修掉的布局 bug

**现象**：统计页三张图全白；课表七列宽度不一致，周六周日被压成窄条。

**根因**：页面内容区用 `GridBagLayout` 排版卡片。当内容高度大于可视区域时，`GridBagLayout` 不是让它溢出滚动，而是**按最小尺寸压缩行**——图表被压到 10px 高（绘制内容从 y=30 才开始，于是整张图都不见了），课表列也按内容最小宽度被压缩成不同宽度。更麻烦的是压缩过一次之后，容器的首选高度也跟着变小，滚动条再也不会出现，形成死锁。

**修复**（`BasePage`）：卡片区改成"每行一个 `GridLayout`、行与行用 `BoxLayout` 堆叠"，并把每行的最小高度锁定为首选高度。行高只由内容决定，空间不够就滚动，不会被压扁。

课表另写了一个 34 行的 `TimetableGrid` 布局：8 列等宽（第 0 列放节次）、表头固定 28px、10 个节次等高，支持课时纵向跨行。不再依赖 `GridBagLayout` 的权重分配。

**验证**：截图对比修复前后；离屏渲染断言图表高度 = 首选高度。

## 八、已知限制（下一版方向）

- 复习提醒仍只在应用内，没有系统级日程提醒（`.ics` 已可绕开这一点）。
- 笔记是纯文本，没有 Markdown 渲染。
- AI 只支持 OpenAI 风格接口，没有做多轮对话与上下文记忆。
- 仍以冒烟脚本验证为主，还没有 JUnit 测试。
